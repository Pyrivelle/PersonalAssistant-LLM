# R1-A：关系与行为逻辑的第一轮改造（事实优先）

## 目标与本轮四项反馈

R1-A 不是“增加好感度提示词”。本轮来源于 E1 真正的 32 题模型报告以及用户的人工反馈：

1. **剧本式演绎**：不是绝对禁止；只有明确请求小说/剧本/角色演绎时允许虚构旁白。QQ/桌面普通交谈默认直接说话，不用括号动作、内心独白和模型思考标签。
2. **技术回答篇幅**：技术场景不自动等于长文章。普通技术咨询先结论再给少数关键证据/步骤；明确要求详细解释、步骤或完整代码时允许展开。没有需要确认的关键缺失条件，不惯性以“你觉得呢？”收尾。
3. **不能编造已经发生的事情**：用户消息、未经验证的 Planner 计划、角色创作、待执行 Skill 或提醒，都不是现实完成事实。关于共同旧事须有可信历史或记忆；关于已发送、已查看、已设置须有实际工具回执。不把拟议行动写成已执行。
4. **边界判断贴近自然交谈**：不要见到“转发别人消息、工具、隐私”等词就立刻机械拒绝；先判断是讨论、假设、创作还是真实要求执行。但**原有宿主身份验证、工具授权、群聊/私聊隔离、实际发送门控仍然有效**；R1 只改语言与行为决策，不给模型新权限。

## 行为逻辑（不是盲目的文本长度裁剪）

\`src/zhuangfy/persona/relationship_behavior_r1.py\` 定义 \`behavior_r1(system_prompt, user_text, channel, tier)\`：生成不包含用户任意指令回显的宿主可信、长度有限的 R1 指导。返回的模式有：

| 模式 | 进入条件 | 输出倾向 |
|---|---|---|
| \`conversation\` | 日常交流；没有明确长文或剧本要求 | 通常 1–3 句话，自然接话，不固定反问 |
| \`technical_concise\` | 技术询问，没有明确要求详细教程 | 直接判断 + 少数必要检查点；不默认长篇列表 |
| \`technical_detail\` | 明确要求详解、完整教程/步骤/代码 | 允许有条理地深入，但不凑篇幅 |
| \`creative\` | 明确要求剧本、小说、角色演绎 | 允许虚构与动作描写；仍明确它是创作而非现实事件 |

以上是**提示策略**而不是可以依赖的语义判定器；复杂上下文仍须通过真实 LLM 的 E1 人工评审来测量。宿主没有在该模块中新增任何持久化关系记录，也没有未经同意读取私聊。

## 关系层级与现实身份

\`tier\` 只能由可信宿主显式传入：\`unassigned\`（当前生产运行时默认）、\`L0\` 初识、\`L1\` 熟悉、\`L2\` 信任、\`L3\` 亲近。**本轮不推断、不自动提升关系、不写好感度数值，也不因为 L3 开启工具权限**。关系级别在当前阶段只是表达建议，不能成为身份凭据或访问许可。

后续 R1-B 可以基于已验证身份、经允许的 Timeline/Curator 与用户明确偏好提供分层证据。实际聊天记忆和执行回执优先于任何角色演绎；现实关系不由《终末地》原作关系直接替代。

## 默认关闭、开启方式与回退

在自己的 \`SenseVoice/cognition_settings.json\` 中增量加入（不要覆盖其他已有设置）：

\`\`\`json
{
  "character_core_v2_enabled": true,
  "relationship_behavior_r1_enabled": true
}
\`\`\`

重启 QQ Bridge / 桌面应用使新的 PlannerSettings 生效。R1 可以单独关闭：

\`\`\`json
{"relationship_behavior_r1_enabled": false}
\`\`\`

启用后，R1 指导进入：
- QQ 的 Planner 和 Replyer；
- 桌面、语音的 Planner 和 Replyer；
- 已经由宿主 B2 核准的主动联络 Replyer（仍需以前相同的授权和时机条件）。

\`src/zhuangfy/llm/providers.py\` 当前只向模型传入约 2000 字 \`emotion_context\`；R1 放在其他可选提示之前，确保真实性策略不会在堆叠 CCV2/E1 规则时被截断。原始用户 Prompt 仍保持用户自定义，不被覆盖。

## E1 真实模型对比入口

手动工作流 \`Character E1 - Real Model (manual)\` 新增：
- \`ccv2_ckv1\`：现有 CCV2 + CKV1 **基线**；
- \`ccv2_ckv1_r1\`：同等条件 + R1-A 行为指导 **待测变体**。

32 个场景和输入数据保持不变。同一测试集中的 \`L0\`–\`L3\` 是**明确标注的合成等级**，不会写入真实 QQ 人物关系。应使用**同一服务商、同一模型、相同版本化人格包和同一场景集**先后跑两次，比较原始答案，最好进行人工盲评。

重点关注 \`everyday_rain\`（旁白、虚构正在做的事）、\`research_qt\`（冗长问题）、\`achievement_fix\`（编造共同排障细节）、\`disagree_privacy\`（没有转发回执却声称转发）、\`initiative_silence\`（只以文字宣布静默）。后两个问题**不是仅凭一段 Replyer 文字能完整证明**的；真正发送、静默与工具状态必须在宿主层用事件轨迹验证。

## 明确的安全与可靠性限制

- **第一版通过“更可靠的行为提示”降低虚构倾向，不能形式化保证模型绝不编造事实**。有证据可用性、回执与后置语义验证问题时，要在后续 R1-B / E1 语义评测单独解决；不是只加一条正则就可以完全防住。
- 普通技术问答**依旧可以在复杂问题或用户明确要求时充分展开**；不是暴力切断长回复。
- 普通聊天默认不写剧本，但对明确创作请求**不应拒绝**，也不应把虚构情节记录成现实个人记忆。
- 不因角色亲近而泄漏真实第三方私密信息；也不因涉及敏感名词就阻止普通解释、讨论或文学创作。
- 所有新功能使用现有原本配置的 QQ/桌面权限；此次 PR 不修改任何 Tool Runtime、成员记忆、长期记忆或主动发送门控。
