# 群聊参与与记忆边界（设计草案）

状态：2026-10-26。第一阶段已在指定白名单群试运行：仅在被明确 `@` 时考虑发言；未 `@` 的群消息只作为本群近期上下文。群级长期记忆和自愿个人档仍待实施。

## 当前实现与上线前缺口

- `qq_bridge.py` 已有群白名单、`@` 解析、群级会话、每群冷却和小时上限。`passive_group_ids` 是单独的非 `@` 参与开关；第一阶段保持为空。
- 当前运行配置已加入一个试运行群，`passive_group_ids` 仍为空。Memory Service 只为准入私聊自动建 PersonID、Timeline 和关系档案；群消息不进入这些私人存储。
- 群级 `DialogueContext` 和短期片段在进程内共用，但聊天流会持久化已处理的群轮次，投递后的图片/工具摘要也可能按群写入本地证据库。不能把“未进入私人 Timeline”描述为“群聊完全不留痕”。
- 群轮次现已允许 Planner 选择 `stop`；Planner 抛错时保持沉默。群消息需要启用 Agent V2 才能进入处理流程。
- 同群 `@` 消息按原始发送者独立排队处理，连续 `@` 不再合并成一个人的发言。未 `@` 的消息保留为最多八条、十分钟内的进程内上下文，供下一次 `@` 的 Planner 与回复参考，不单独触发回复。上下文中的说话人优先显示群名片、其次 QQ 昵称，并附带 QQ 号作为稳定标识；昵称不用于身份或记忆授权。队列最多容纳 32 条等待消息；真实群仍需验证消息时效。
- 现有群冷却与小时上限只是防刷限制，不等于“这句话值得插话”的判断。第一阶段不得据此启用非 `@` 自然参与。

## 第一阶段：仅 `@` 的群聊

1. 宿主先检查真实 OneBot 群号、发送者、消息 ID、白名单和重复消息。群昵称只用于显示，不用于合并身份。
2. 每条 `@` 消息独立成为一个待判断轮次，保留来源、时间与发送者；未 `@` 的公开发言只进入短期上下文，不能拼成同一个人的发言，也不启动模型轮次。
3. Planner 可选 `reply`、短时 `wait` 或 `stop`。明确邀请回答、询问庄方宜的意见或延续与她的对话时才考虑回复；群友之间交谈、单纯表情、无明确对象的消息和已经过时的话题可保持沉默。模型/工具失败时默认不发群消息。
4. 群回复针对触发轮次的问题，短而有内容，发送时不自动 `@` 任何人；不公开任何人的私聊、个人档案、关系层级或未获许可的历史事实。`@` 也不保证一定回复。
5. 每群保留可配置冷却和上限；默认禁用主动群发、非 `@` 插话、私人记忆检索及外部搜索工具。试运行群可通过独立 `voice_group_ids` 白名单，在被 `@` 且本轮明确要求语音时发送短语音；合成失败不自动改发文字。回复只有 OneBot ACK 后才记为已送达。

## 群档、成员档与跨场景共享

| 信息 | 存放位置 | 可在何处使用 |
| --- | --- | --- |
| 近期群消息 | 以 `(bot_id, group_id)` 隔离的短期上下文 | 仅本群，带真实发送者与时间；不自动建个人档 |
| 群共同事项 | 群级记忆，附来源消息、记录时间、可见范围、失效/删除状态 | 仅本群；记录群规则、公开计划和共同讨论，不把旁人评价写成某人的个人事实 |
| 自愿个人档 | 已验证 QQ 账号对应的 PersonID，另有逐群参与/记忆授权 | 该人的授权范围内；群昵称和其他成员的发言不能代替本人确认 |
| 私聊记忆与关系 | 既有 PersonID 私人存储 | 默认只在该人的私聊使用；即使同一人在群里也不得自动带入 |

群级记忆和个人记忆采用**分层引用、默认不互相复制**。用户可在私聊中自愿确认群成员身份，并逐项允许把自己在某群亲自说过的内容整理入个人档；群里他人对他的评价不得自动进入个人档。反向公开私人记忆也须由本人明确指定具体内容和目标群。每个群的授权、撤销与删除独立；同一 QQ 账号跨群可解析为同一已验证 PersonID，但不同群的内容仍按群隔离。

群级长期记忆应只收录可核对来源的公共事项，不自动汇总每位成员的完整画像。新加入群的成员先是临时参与者，不因一次 `@`、群名片或昵称创建长期个人档。群管理员启用群级留存前，应有清晰的告知、保留期限、查看/纠错和删除入口；原始群聊天与提炼出的摘要需分别管理。实现中应给群记忆与个人记忆独立的授权字段、审计和删除联动，不借用现有私聊 `timeline` 同意。

## 实施与验收顺序

1. 已修复群 `stop`、Planner 失败时沉默和跨发送者合并；离线 OneBot 事件覆盖 `@` 回复、不回复、连续多人 `@`、限流和 ACK。真实群仍需验证回复目标、消息时效和重复事件。
2. 在一个明确授权的白名单群先做 `@` 测试；保持 `passive_group_ids` 为空，不导入任何私人记忆。
3. 建立独立的群级记忆模式：群授权、来源、保留/删除、管理员查看；默认不提炼个人档。
4. 加入自愿个人档和逐群授权、本人确认、跨群/私聊共享的逐项许可与撤销测试。
5. 只有在上述隔离、误回率和退出机制稳定后，再单独讨论非 `@` 自然参与及主动触发。

目标群已由项目负责人指定，机器人已入群，白名单试运行已开始。群级长期留存的告知方式、期限及管理员入口仍待确定；本文不启用群级长期记忆或个人档。
