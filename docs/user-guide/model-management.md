# 模型管理

在 ZhuangFY 控制台的「模型管理」中，先建立供应商连接，再登记模型，最后进入「功能分配」选择 Planner、回复、识图与记忆整理使用的模型。每个模型有一个全局唯一、保存后不可修改的本地「模型标识符」；「API 模型 ID」是实际发给供应商的名称，同一供应商可以配置多个模型。

首次打开时，页面从已有 `model_routes.json` 和记忆服务设置读取现有模型，不会自动改写配置。首次保存后，本地 `model_registry.json` 保存供应商与模型元数据，现有 `model_routes.json` 仍是 QQ、语音及桌面会话读取的运行时路由。密钥仅保存在 `.env.local`，不进入模型目录文件；供应商密钥按供应商标识与 API 地址绑定。设置供应商密钥后，该连接下的模型优先使用它；未设置时仍可沿用原有的模型专用密钥。

Planner、回复和识图的候选按「首选模型、备用模型」顺序尝试。记忆整理只使用一个模型，切换后需重启记忆服务；QQ 桥接对新的路由配置需重启连接。现有 Embedding 服务仍由记忆系统独立配置，此页暂不分配 Embedding 模型。

模型名称用于界面显示；API 模型 ID 只在编辑窗口和悬停提示中查看。DeepSeek 官方与硅基流动模型可将思考模式设为「沿用模型默认」「启用」或「关闭」，对应当前 `chat/completions` 请求。模型行的「测试」会向选定模型发出一条内置短请求，验证密钥、模型 ID 和回复接口，并显示耗时、简短回复或错误原因；这会消耗少量 API 额度，不会写入对话或记忆，也不会自动尝试备用模型。价格、温度、最大 Token、选择策略和联网搜索控件目前置灰，暂不改变模型请求。DeepSeek 官方虽提供 Responses API 原生联网搜索，但 ZhuangFY 尚未接入该协议。
